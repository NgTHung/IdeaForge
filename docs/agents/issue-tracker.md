# Issue Tracker: IdeaForge Tasks

Engineering skills use the version-controlled `.tasks/` project as IdeaForge's issue tracker. Use `taskroot` for task creation, queries, lifecycle changes, validation, and triage tags.

`docs/task-tracking.md` defines the authoritative task schema and command behavior.

## Before changing tasks

Run:

```bash
taskroot validate
taskroot list
```

Use exact `domain:LOCAL-ID` identities. Select domains, prefixes, task types, milestones, and ordinary tags from `.tasks/config.json` and related tasks.

Run both commands again after changing tasks.

## Fetching an issue

Inspect structured task context:

```bash
taskroot show work:WORK-001 --format json
taskroot context work:WORK-001 --format json
```

Read the Markdown task file when you need body sections or triage notes.

## Publishing an issue or spec

Create one task per issue or spec through `taskroot add`. Preserve the criteria section required by the selected task type.

A published spec may add its specification sections to the generated task body. Use `parent` for hierarchy and `depends_on` for blocking relationships.

Choose the domain and ID prefix from related work. Development work belongs in the `work` domain. Release gates belong in `milestones`.

## Publishing tickets

Create one task per approved ticket in dependency order.

- Use `parent` to connect tickets to their containing effort.
- Use `depends_on` for blocking edges.
- Apply `ready-for-agent` only when the ticket is specified for implementation.
- Use `taskroot ready` to determine whether dependencies and hierarchy permit execution.

Do not modify or close a parent task unless the user requests it.

## Triage

Triage category and state are exclusive task tags. Change them through:

```bash
taskroot tag set work:WORK-001 triage-category enhancement
taskroot tag set work:WORK-001 triage-state needs-triage
taskroot tag clear work:WORK-001 triage-state
```

An untriaged task has no `triage-state` tag. Find active queues with:

```bash
taskroot list --tag needs-triage --format json
taskroot list --tag needs-info --format json
taskroot ready --tag ready-for-agent --format json
```

Triage tags do not replace lifecycle status. Use `block` only when missing information genuinely blocks progress. Use `obsolete` with a rationale when an approved triage outcome is `wontfix`.

Append discussion to `## Triage Notes` in the task body. Notes generated by the `triage` skill must start with its required AI disclaimer. Use Git history when authorship or timing matters.

## Wayfinding

Use a parent Epic or Design task as the map and child tasks as tickets.

- Store Notes, Decisions So Far, and Fog in the map body.
- Set each child task's `parent` to the map.
- Store blocking edges in `depends_on`.
- Query children with `list --parent`.
- Inspect each candidate with `context`; a frontier task has `readiness.ready` set to `true`.
- Claim work with `start`.
- Record the answer, complete its criteria, and resolve it with `done`.
- Add a short context pointer to the map's Decisions So Far.
